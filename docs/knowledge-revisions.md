# 知识库版本历史

版本历史保存在工作区 SQLite 的 `knowledge_revisions` 表中，与稳定文档 ID 关联。本地文件同步继续经过原有版本号及文件指纹检查。

## 手动保存

正文日常自动保存及 Ctrl+S 不创建历史。只有主动“保存版本”并填写名称才记录已保存的当前内容；草稿保存失败或版本冲突时中止。版本长期保留，不设时间或数量上限，可重命名或删除。普通编辑、AI 修改、提案应用、外部文件同步、迁移、备份合并和历史恢复均不自动留档。

历史包括正文、标题、标签、知识库、文件夹、日期及文档角色；UTF-8 文本原件另外保存 BOM、原件校验值及文件属性；不包含图片、Office、PDF 或音视频原件的旧副本。图片能否显示仍取决于资源是否存在。

## 对比与恢复

列表直接读取版本摘要，选择版本后才重建正文。恢复前先保存草稿、展示确认，再携带当前 `baseVersion` 提交；失败或冲突会中止。恢复默认保留当前位置，可勾选恢复历史位置。恢复不会自动保存恢复前内容，需要保留时请先主动保存版本。网络中断导致结果不明时，界面核对当前内容，不自动重放请求。

## UTF-8 文本原件

TXT、JSON、CSV 和代码等注册文本格式可在文件阅读区选择“编辑原文”。CSV 按原始文本编辑，不提供表格单元格编辑。普通 Markdown 笔记沿用原编辑器。原文读取、保存版本和恢复均使用完整文件，而不是用于搜索的提取文字。

严格验证 UTF-8，并单独保存 BOM。编辑状态保留原始 CRLF、CR、LF、空白和末尾换行，编辑器只替换实际修改的区域，不执行格式化或 Markdown 链接改写。默认最多 50 万字符，并受原有 2 MiB 请求体限制；其他编码、超限或疑似二进制的文件只读并提示原因。

原文编辑支持自动保存、Ctrl+S 及切换前保存。写入需要匹配 `baseVersion` 和 `baseFingerprint`，外部文件变化返回冲突并保留草稿；请先同步原件再恢复草稿。未启用文件夹同步时，原件冲突草稿保存在账户数据目录 `.liuxu/conflicts/`，可在知识库设置中恢复。原件版本与 Markdown 批注版本分别管理。

`GET /api/knowledge/files/:id/text` 返回完整原文、BOM、版本、指纹和编辑能力；`PUT` 同一路径保存原文并同步内部原件、文件属性、搜索索引和预览。非 UTF-8/超限以只读能力返回，文件缺失或指纹冲突返回 404/409。历史保存与恢复请求对文本原件同样要求 `baseFingerprint`。

## 思维导图

版本保存节点 ID、文字、位置、连线、折叠状态、根节点和画布配置，不保存截图。保存版本前提交正在输入的节点文字并保存草稿。历史详情从模型生成历史与当前的只读导图，支持缩放和拖动，另提供 JSON 文本对比。恢复前校验模型结构，恢复后重新加载编辑器。

## 差异存储

首个版本保存完整正文，后续版本参照上一条手动版本，最多连续 9 条差异后重新保存完整基准。属性每版完整保存。正文差异以保留换行、空白和 Unicode 的多段替换操作表示，与页面红绿对比展示无关。差异存储不小于完整快照或计算超过预算时直接保存完整快照。

文本原件和新导图快照使用 full-v2/delta-v2 类型化格式与确定性校验序列化；legacy/full-v1/delta-v1 继续可读，不重新清理既有历史。格式、基准 ID、基准及目标校验值用于验证准确重建；基准缺失或校验失败会报错并阻止恢复。删除版本时先把直接依赖它的记录转为完整快照，再在同一事务中删除，其他版本 ID、名称和内容保持不变。

## 升级与备份

数据库迁移版本 7 增加差异存储字段，并标记升级前的旧历史。工作台保存草稿后事务性清理旧历史（包括命名版本），同时记录完成标记；仅执行一次，不修改当前正文，也不主动从知识库文件夹覆盖内容。第一次主动保存版本时才创建基准。

已有备份文件保留。SQLite 工作区 ZIP 备份包含完整历史及差异依赖；恢复备份保留其中历史并跳过一次性清理，旧完整快照仍可读取。文档删除仍级联删除其历史。JSON 备份沿用原有范围，不包含版本历史；需要保留历史请使用工作区 ZIP。

版本详情及恢复继续返回完整 `snapshot`。兼容 checkpoint 接口校验目标后返回 `checkpointed: false`，不创建历史。差异存储降低数据占用和后续增长，但 SQLite 空闲页会复用，文件不保证立即缩小，不自动执行 `VACUUM`。
