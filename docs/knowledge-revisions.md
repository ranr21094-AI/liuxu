# 笔记版本历史

版本历史用于找回笔记正文和编辑字段的旧状态。它保存在工作区 SQLite 的 `knowledge_revisions` 表中，和稳定文档 ID 关联；本地文件同步继续经过原有版本号及文件指纹检查。

## 快照规则

- 普通编辑按五分钟窗口记录一次变更前状态，未命名历史最多保留 50 条且不超过 30 天。这不是逐次保存记录。
- AI 工具直接写入、应用笔记助手修改提案、外部 Markdown 同步覆盖，以及历史恢复前，都会保存额外快照。
- 用户可为已保存的当前笔记创建命名版本。命名版本不参加自动清理，可在历史详情中重命名或删除。
- 历史包含正文、标题、标签、知识库、文件夹和日期，不包含图片或其他附件二进制的旧副本。

## 对比与恢复

历史列表在选择一条记录后才读取完整正文。对比展示正文和标题、标签、日期、位置。恢复默认覆盖正文、标题、标签和日期，同时保留笔记当前位置；如需要，也可勾选同时恢复历史位置。

恢复前会先保存编辑器草稿，再展示确认，并携带当前笔记版本号提交。冲突或保存失败会中止恢复并保留草稿。服务端再次校验版本、文档权限和日记解锁状态，并把恢复前状态作为新快照保存。网络断开造成结果不明时，界面先读取当前文档核对，不会自动重放恢复请求。

图片引用随 Markdown 正文恢复，但图片文件没有版本副本。图片能否显示取决于当前本地资源是否仍存在；恢复到旧位置时按知识库文件夹同步服务的移动与相对路径规则处理。

## 存储兼容

数据库迁移版本 5 为历史表增加可空命名字段；现有历史内容无需转换。完整 SQLite 工作区备份会带上新字段，旧 SQLite 及 ZIP 在启动或恢复时由迁移补齐字段。文档删除仍会级联删除该文档的历史记录。

历史接口沿用文档 ID 和日记权限检查：列表及详情为只读；命名快照创建需要匹配当前 `baseVersion`；改名与删除只作用于命名版本；恢复接受可选 `restoreLocation` 参数。旧客户端未发送该参数时维持原来的完整恢复行为。
