# 本地文件工作区性能实测（2026-10-14）

平台：macOS arm64，Node 24.20.0。本地临时目录与隔离 SQLite，每个请求类别 30 个样本，搜索和磁盘缓存已预热。HTTP 读取、保存与搜索采样期间启动一次后台完整核对；后续完整核对包含排队索引清空。没有读取真实用户数据。

| 文档数 | 首次发现及索引 | 完整核对 ms | 打开 P50 / P95 ms | 保存 P50 / P95 ms | 搜索 P50 / P95 ms | 事件循环 P95 ms | RSS MiB |
|---|---|---|---|---|---|---|---|
| 1,000 | 3.37 秒 | 288.4 | 1.60 / 1.97 | 19.14 / 24.21 | 3.46 / 4.89 | 3.11 | 218.0 |
| 10,000 | 37.87 秒 | 2898.2 | 1.45 / 8.90 | 22.89 / 28.08 | 6.53 / 10.01 | 2.28 | 420.7 |

原始报告：[千条](performance-file-workspace-2026-10-14/1000.json)、[万条](performance-file-workspace-2026-10-14/10000.json)。

复测观察：万条数据多轮首次发现约 36–39 秒，需为所有新文件建立身份、旁路记录和索引。后台核对期间打开/保存比空闲状态慢，过往不同修订的万条保存 P95 在约 26–62 ms 范围；不能据此宣称稳定达标。不同修订和同时运行的测试会影响比较，报告不将这些样本合并成一个分位数。

这些数据测量单个编辑文档和本地热缓存，内存是测试进程 RSS，不代表 Electron 总内存；首次启动不是真正冷磁盘。没有网络盘、Windows 或打包应用性能数据。另有隔离 Electron 编辑/自动保存/重命名实测和 macOS 原生监听实测；它们不属于本表性能样本。

复现：

```sh
PERF_BACKGROUND=1 PERF_DOCS=1000 npm run perf:files
PERF_BACKGROUND=1 PERF_DOCS=10000 npm run perf:files
```
